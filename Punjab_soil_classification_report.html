Phase 1

Ground-Truth Polygon Collection Complete

Ground-truth polygons delineating known soil texture zones were manually collected across 16 Punjab districts. Each polygon was labelled with a soil type (S1–S4) based on field knowledge and existing soil maps. The four classes correspond to:

S2 Sandy loam soils
S3 Loam soils

Tooling: A custom Python script (data_proc.py) parsed the per-district CSV files and automatically generated a Google Earth Engine JavaScript FeatureCollection (gee_features.js) containing all 35 polygons with their soil type and district labels — ready for direct paste into the GEE Code Editor.
Phase 2

Sentinel-2 Data Download via GEE Complete

Sentinel-2 Level-2A (Surface Reflectance) imagery was acquired for the bare-soil observation window (1 April – 1 May 2024), which is the post-Rabi harvest, pre-Kharif sowing period when agricultural fields are maximally exposed.

GEE Export Strategy

Rather than a single large export (which consistently timed out), one independent task was submitted per polygon — 35 tasks total.

Pre-processing Applied

  • ☁️ QA60 cloud mask — bits 10 & 11
  • 🌫️ SCL shadow mask — classes 3, 8, 9, 10
  • 🌾 ESA WorldCover — cropland-only mask (class 40)
  • 📊 Temporal median — across all valid acquisitions

Export Parameters

Bands exported B2–B8A, B9, B11, B12 (11 bands)
Spatial resolution 10 m
Cloud threshold < 20% per scene
Pixels per polygon 25,000 (random sample)
Output format CSV per polygon → Google Drive
Total tasks 35
Why 25,000 pixels per polygon? After bare-soil filtering, roughly 10–60% of pixels survive (depending on the polygon). Capping at 25,000 ensures each GEE task remains lightweight and reliable while still providing ample training signal — especially for the later SMOTE oversampling step.
Phase 3

Bare Soil Detection & Dataset Creation Complete

The 35 downloaded CSVs were passed through a pre-trained XGBoost bare-soil classifier (xgb_bare_soil.joblib) to retain only pixels where the land is genuinely bare and unoccluded. This is critical: feeding vegetated or mixed pixels into a soil texture model would introduce severe spectral noise.

Index Formulae

# Bare Soil Index BSI = ((B11+B4)-(B8+B2)) / ((B11+B4)+(B8+B2)) # NDVI NDVI = (B8 - B4) / (B8 + B4) # NDWI NDWI = (B3 - B8) / (B3 + B8) # SWIR Ratio SWIR_ratio = B11 / B12 # Brightness Brightness = (B2+B3+B4+B8) / 4

Class Imbalance — SMOTE

Synthetic Minority Over-sampling Technique (SMOTE) was applied exclusively to the training set (80% split) to balance all four classes to equal representation before model fitting.

Model Comparison Results

Three models were trained and evaluated on the held-out 20% test set (21,580 pixels). The primary metric is Macro F1, which gives equal weight to all four classes regardless of their natural frequency.

Why do boosting models (XGBoost, LightGBM) underperform? Sentinel-2 spectral bands for adjacent soil types are highly correlated and spectrally similar. Random Forest's independent bagging with balanced class weights handles this covariate structure better than sequential boosting, which tends to over-focus on the dominant class (S4) in early rounds.

Feature Importance (Random Forest)

The SWIR ratio (B11/B12) is the single most discriminative feature, confirming that shortwave infrared reflectance patterns are the primary spectral signal distinguishing Punjab soil textures.

Limitations & Future Work: The current model Macro F1 of 0.623 reflects the inherent spectral ambiguity between adjacent soil texture classes in a single-date median composite. Model performance could be improved by (1) incorporating multi-temporal features across the bare-soil window, (2) adding terrain variables (DEM, slope), (3) expanding training polygons for the underrepresented S3 class, and (4) exploring deep learning approaches (e.g. 1D-CNN on spectral profiles).
